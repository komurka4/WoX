# Developing

A short guide for people who want to read, change or extend the source. Building is described in
[BUILDING.md](BUILDING.md); the layout of the source in [SOURCE_ARCHITECTURE.md](SOURCE_ARCHITECTURE.md); formatting,
naming and comment rules in [CODING_STYLE.md](CODING_STYLE.md).

## The principle: behave like the original

The engine reproduces the original DOS program's behaviour, including its quirks, integer overflow and signedness,
evaluation order, random-number use and timing, wherever these were established from the original program. When you
change engine code:

- Keep the original's behaviour as the default. A deliberate difference belongs in an **add-on** (`src/addon/`,
  `include/xeen/addon/`) or a **bug fix** (`src/bugfix/`), switched off by default and enabled in `wox.cfg`.
- Each function's documentation comment names the original routine it reproduces by its *analysis address*
  (`segment*16 + offset` with the original program loaded at linear 10000h). Keep these references; they are how a
  change can be checked against the original.
- Where the engine meets a case it cannot reproduce faithfully, it **stops with a message** at the original routine's
  address instead of guessing (see "When the game stops" in [CONFIGURATION.md](CONFIGURATION.md)). Replace such a stop
  only with behaviour established from the original.
- Host code (window, input, audio output, files, configuration) lives in `src/platform/`, `src/app/` and
  `src/audio/`, never in the game rules.

## Generated files

| What | Generated from | When |
|---|---|---|
| `BUILD/generated/program_data.c` | `src/data/` (generated by the user from `XEEN.DAT`, [src/data/README.md](../src/data/README.md)) by `tools/data/gen_program_data.py` | every build (CMake) |
| `BUILD/version/*` | `versions.cmake` through `cmake/xeen_version.*` | every configure ([VERSIONING.md](VERSIONING.md)) |
| `BUILD/icons/*` (window icons, `.ico`, resource scripts) | `icon/wox_icon.bmp`, `icon/setup_icon.bmp` by `src/icon/make_icons.py` | every build (CMake) |
| `src/addon/*/*.inc` tables (committed) | scripts beside them (`make_table.py`, `make_icon.py`, `quest_journal/tools/`) | by hand; some read the original game files (`XEEN.CC`, `DARK.CC`, `*.CUR`) or the program data |
| `tests/phase335_zip_vectors.h` (committed) | `tests/phase335_make_zip_vectors.py` | by hand |

Never commit the program data, original game files, saves, ROMs or CD audio. `.gitignore` lists them, but check
`git status` before committing.

## Tests

`ctest --test-dir build/dev --output-on-failure` runs the public test set (see [tests/tests.cmake](../tests/tests.cmake)):
headless unit and contract tests of the rules, events, combat, scene, platform layer (against mock Win32 and Xlib
APIs), configuration, setup model and versions. Their expected values were established against the original program
during development. The development project also has a much larger regression suite that runs the original
program's code in an emulator side by side with the native code; it needs the original game files and is not part
of this repository, so changes to game behaviour cannot be fully re-verified from this tree alone.

## Formatting

`clang-format` 18 with the repository's [`.clang-format`](../.clang-format); the paths in
[`.clang-format-ignore`](../.clang-format-ignore) (vendored code, hand-laid tables, add-ons and bug fixes) are not
reformatted.
